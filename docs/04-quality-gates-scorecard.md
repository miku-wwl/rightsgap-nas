## Gate G0 — Capability fidelity

- Current official kit version, checksum, catalog mapping and checker source inspected.
- No invented CLI, Expert Agent, Action parameter, output field or permission.
- Core document citation and source-scoped retrieval capability judged feasible from real official definitions.
- Any unsupported critical requirement causes explicit narrow/pivot decision.

## Gate G1 — Evidence safety

- CONSISTENT_EVIDENCE is emitted only when each evaluated dimension has credible sourced support and no unresolved contradictory evidence.
- Licensee/applicant identity is explicitly assessed, not assumed from purpose/date/territory alone.
- Unknown scope, truncated results, missing path, uncertain join or unsourced quote cannot produce a positive status.
- Test target: zero falsely positive evidence statuses in pre-labeled negative cases.

## Gate G2 — Counterfactual correctness

- Changing Scenario A to B changes only evidence conclusions justified by changed inputs.
- Same source corpus and same scenario should yield materially consistent output on recheck, subject to observed model variability.
- User-added amendment is never treated as automatically superior to earlier conflicting documents.
- Proof-Carrying Delta explains actual changed fields, source clause and uncertainty.

## Gate G3 — Approval and least privilege

- Read-only audit; optional report save must use documented state-changing expert and platform approval.
- Denied approval or permission blocks the dependent operation without hidden side effects.
- No delete, move, rename, share, tag or publish operation in MVP.
- No external data egress claim without inspecting actual configured model route.

## Gate G4 — Uliya technical validation

- Official static checker reports zero errors and zero warnings on exact Skill package.
- All delegate targets, evidence mappings, names, frontmatter, referenced files and sections are valid per current kit.
- Local synthetic/mocked tests are reported separately from an actual device run.
- If selected, the same core Skill must install and run on assigned NAS; record actual results and failures.

## Gate G5 — Judge-facing clarity

In a three-minute real NAS video, show:

1. An authentic source and user-defined intended use.
2. A real status difference from a changed use scenario.
3. Citation and source-coverage proof, not a legal verdict.
4. A missing/unreadable case handled conservatively.
5. Approved save only if it truly works on the assigned NAS.

## Kill criteria

- Only free-text summaries with no trustworthy source path/quote are available, yet the design needs verified clauses.
- No reliable mapping between source agreement and asset.
- Mandatory flow requires direct CLI, custom runnable Skill code or bypassing permission gateways.
- A positive rights claim cannot be made safely with the actual expert output.

If any occur, narrow to an evidence locator/review assistant or pivot; do not merely relabel the failure as a feature.
